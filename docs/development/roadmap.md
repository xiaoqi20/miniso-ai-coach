# 工程化路线图

## M1 本地三角色闭环

用一款新品、两家门店，以及总部运营、员工、店长三个角色，在同一套 Vue、FastAPI、MySQL 环境中走通 **审校发布 → 员工学习 → 文字对练 → 店长指派补训 → 员工复练 → 店长复查 → 48 小时统计**。首轮使用开发身份和可重复的模型替身。测试数据沿用原型中的商品与考点，正式成绩由新系统产生。 [工程化验收约定](../../AGENTS.md) · [流程审查](../project-execution-review.md)

| 顺序 | 工作 | 任务 |
| --- | --- | --- |
| 1 | 确定身份、课程版本、评分状态及 API 契约 | [T001](tasks/T001-contract.md) |
| 2 | T001 验收后，数据与会话底座、员工 H5 和公共前端入口可并行；T006 仅由 Antigravity App 实现 | [T002](tasks/T002-backend-foundation.md) · [T006](tasks/T006-employee-h5.md) |

| 4 | 合并三角色界面与业务接口，运行端到端验收 | [T008](tasks/T008-e2e.md) |

### 里程碑验收

- 总部审校后向门店 A 定向发布。门店 A 员工可以学习，门店 B 员工看不到该批次。双方均无法通过直链接口读取草稿或越权读取对方数据。
- 学习进度和对练轮次落库。刷新页面或服务重启后可以恢复。重复提交返回同一份正式成绩，并发轮次、评分和复查不会互相覆盖。
- 以「端盒 6 个不重复」验证正确、同义表达、漏讲和事实错误。店长针对漏讲指派补训，复练仍漏讲时保留待办，改正后进入待复查，由授权店长确认，记录操作人和时间。
- 48 小时通关率使用发布时的应训名单及服务端记录的发布时间与通关时间，验证修改成员名册和重复对练均不会使历史分母或去重结果发生偏移。

## M2 真实环境联调与试点

M1 验收后，由 Codex 将下列事项拆成可领取的任务卡。可提前准备环境和测试素材。

| 工作 | 启动条件 | 验收结果 |
| --- | --- | --- |
| 企业微信接入 | 试点企业、应用配置、HTTPS 回调及测试账号就绪 | iOS 和 Android 可从工作台进入，企微身份映射到正确岗位及门店。总部按确认的桌面入口登录 |
| 真实模型和评分回归 | 模型服务配置和经业务确认的标注样本就绪 | 结构化评分、知识边界、超时重试和流式体验可验证 |
| 移动端语音 | 语音方案、设备及测试账号就绪 | 企微 iOS 和 Android 上验证权限、识别、降级和文字回退 |
| 总部资料导入和试点运营 | 样例商品资料、审校人及应训名单就绪 | 从资料导入到审校发布、补训复查和 48 小时复盘可以重复执行 |
